## 待回答的两个问题（P2/P4 依赖）

- 任务重跑是否重复下载：**不会重下已记录的章节**。全量任务从 `last_epi + 1` 开始，已完成的章节不会重下；但被中断任务里"已下载但序号小于最大值"的章节无记录。P2 队列持久化需要考虑。
  - P2 核对结论（`b91e245`）：持久化后恢复的全量任务同样从 `last_epi + 1` 开始，无需额外的跳过逻辑。并发 >1 时若较大序号章节先完成、较小序号章节被中断，后者不会补下——这就是 F9，维持现状。
- `library/short`、`library/paginate`、`library/search` 的调用方：新旧前端代码里都没有调用，仓库内无其他使用者。是否有仓库外的调用方需用户确认。（最终评审后由仓库所有者决定删除，见 `docs/api-contract.md` 第 5 节。）

- [ ] 对一部已用 Flask 下载过的连载漫画触发更新：新章节的压缩包名与旧章节风格一致（如 `第68-第69话`、`v$2`），目录中没有出现同一话的两种命名

- [ ] 下载中断网几分钟：失败 ≥10 张的章节不产生压缩包，`last_epi` 不前进；下次扫描会重试
